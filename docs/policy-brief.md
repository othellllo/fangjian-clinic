# 医保政策与合规要点（2026-11 调研）

> 目的：为「方笺」的追溯码、医保结算、打印、政策维护功能提供依据。
> 声明：本文是工程实现参考，不构成合规意见；各地经办机构执行口径不同，
> 上线前必须与当地医保经办机构确认技术规范。

## 一、三条硬性结论（直接影响系统设计）

1. **药品追溯码已是法定义务，不是可选项。**
   《医疗保障基金使用监督管理条例实施细则》（国家医保局令第 7 号，2026-02-12 公布，
   **2026-04-01 施行**）第九条要求定点医药机构"积极应用医保码、视频监控、医疗保障信息业务编码、
   药品耗材追溯码，及时通过医疗保障信息系统全面准确传送……数据"；
   第二十四条明确：**未按规定使用药品耗材追溯码的，可依条例第三十九条第三项处罚**。
   来源：[国家医保局原文](http://www.nhsa.gov.cn/art/2026/2/13/art_173_19681.html)

2. **药品销售环节"无码不结算"**：2025 年 7 月 1 日起，药品销售需扫追溯码方可进行医保结算
   （[国家医保局办公室公告](https://www.gov.cn/zhengce/zhengceku/202410/content_6978005.htm)
   + 各地医保局部署，媒体解读见 [央广网](https://health.cnr.cn/yg/20250321/t20250321_527108282.shtml)）。

3. **但中药饮片、院内制剂暂不强制采集。**
   公告明确："对于药监部门尚未要求赋追溯码的药品（**中药饮片**、院内制剂等），
   以及一类医疗器械，暂无须采集追溯码信息；住院患者必须拆零发放的药品、术中医用耗材、
   零散注射针剂，暂无须采集。"
   → **中医馆的关键判断：中药饮片处方（含代煎）不强制扫码；中成药、西药、二三类耗材必须扫码。**

## 二、对系统的具体改造要求

### 1. 追溯码模块

| 环节 | 要求 |
| --- | --- |
| 药品字典 | 每个药品标记"是否需采集追溯码"（HERB/院内制剂默认否，PATENT/WESTERN/MATERIAL 默认是） |
| 入库 | 扫码绑定：追溯码 ↔ 批次 ↔ 药品；支持一串多码连续扫；重复码/不存在的码要拦 |
| 发药 | 需追溯药品发药时逐盒扫码；**未扫码不允许走医保结算**，自费可放行（但建议同样记录） |
| 上传 | 通过 `TraceUploadProvider` SPI 上传医保平台；未接入时记录为"待上传"，可导出补传 |
| 追溯查询 | 按码反查：药品、批次、入库时间、发药时间、患者、处方、操作人 |
| 退药 | 追溯码状态回退为"在库"，并记录退药流水 |
| 留存 | 法规要求配合检查、不得清除历史数据（细则第十六条第六项）→ 只增不删，导出留痕 |

### 2. 医保结算前置校验

- 收费单里含"需追溯"药品且未采集追溯码 → 禁止选择医保支付方式（`INSURANCE`），
  允许现金/微信等自费方式，并提示原因。
- 医保结算必须走当地经办机构接口，系统只做**编排与留痕**，不自行计算报销（
  报销规则随地区、险种、目录版本变化，硬编码必然出错）。

### 3. 打印要素（票据与处方）

**收费小票（58/80mm 热敏）**：机构名称、票据号、日期时间、患者姓名、项目明细（名称/规格/数量/单价/金额）、
合计、支付方式、医保支付/个人自付（如有）、收费员、退费标识。
**处方笺（A5/A4）**：机构名称、患者信息、诊断（中医证型）、药品明细（名称/规格/剂量/数量/用法）、
剂数、煎法、医师签名、审核药师、金额、打印时间、页码。

> 注意：纸质处方与电子处方的保存期限、签名要求按当地卫健/药监规定执行，系统留档不少于规定年限。

### 4. 政策维护（"及时更新政策"怎么落地）

**结论：不要让系统自己去网上抓政策。** 理由：
- 政策以官方发布为准，抓取会有版本错漏、断章取义风险，出了事系统背锅；
- 各地执行细则不同，同一份国家文件在本地有补充规定；
- 政策变更往往要同步改"参数"（起付线、报销比例、目录、限价），不是改一段文本就完事。

**正确做法（系统已按此实现"医保政策库"）**：
1. 结构化登记：标题、发文机关、文号、分类（追溯码/结算/目录/收费价格/监管）、
   发布日期、**生效日期**、失效日期、摘要、正文、来源链接。
2. **版本与变更留痕**：正文不可硬删，编辑走审计日志（已有）。
3. **到期提醒**：生效前 30 天、失效前 30 天在首页/政策库提示。
4. **参数联动**：政策条目可关联系统参数（如报销比例、起付线、限价），
   改政策时同步给出"需要调整的参数清单"，避免只改文档不改配置。
5. 政策来源以官方链接为准，系统只存摘要 + 链接 + 关键条款摘录。

### 5. 数据留存与导出

- 细则要求配合检查、不得"故意清除法定或约定合理保管期限内的历史数据"（第十六条第六项）。
- 因此：患者、病历、收费、库存、追溯、审计 **只增不删**；导出功能必须记录导出人、时间、范围（审计已覆盖写操作，导出也纳入审计）。
- 导出格式优先 CSV（Excel 直接打开，UTF-8 BOM），避免用户被系统锁死。

## 三、需要与实施方/当地经办机构确认的问题

1. 当地医保接口技术规范（结算、退费、对账报文格式）与测试环境账号。
2. 药品追溯码上传接口（国家平台/省平台）、是否要求实时上传、失败重试策略。
3. 是否要求电子处方流转（处方外配）、电子签名。
4. 收费票据是否必须使用财政/税务监制票据（涉及票据印刷与票号管理）。
5. 小票机型号与纸宽（58mm / 80mm）、处方笺纸张（A5/A4、是否预印）。
6. 中医馆是否被认定为"定点医疗机构"、能否开展门诊统筹结算（各地差异极大）。
